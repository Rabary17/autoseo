1 Régénérer les candidats (si les bases factuelles ont changé)

À relancer uniquement si data/factuel/*.json a été mis à jour (nouveau lot de codes OBD, nouveaux modèles...). Réinitialise tous les candidats non encore validés à « à valider » — ne touche jamais un candidat déjà retenu/rejete.

Régénération des candidatsgratuit
python scripts/expand-moteurs.py
Lit data/factuel/*.json, compose les mots-clés par formule (prestation×marque, code OBD, modèle×angle...), écrit data/keywords/moteurs-candidats.json + .xlsx. Fermer le fichier xlsx dans Excel avant de lancer (verrou Windows sinon).

2 Vérifier avant de dépenser (aucun coût)

Simule toute la logique de lots/seuils/reprise sans le moindre appel réseau ni la moindre écriture réelle. À faire à chaque fois qu'on modifie le script de validation.

Test à blanc (dry-run)gratuit
node scripts/validate-moteurs-haloscan.js --dry-run
Simule la validation avec des volumes fictifs. N'écrit rien sur disque, ne consomme aucun crédit. Sert uniquement à vérifier que le lotissement et les seuils se comportent comme attendu.

3 Valider pour de vrai consomme des crédits

⚠️ Ne lancer qu'après validation explicite — ceci dépense le pool creditBulkKeyword réel. Reprend automatiquement là où un run précédent s'était arrêté (ne revalide jamais un candidat déjà traité).

Run réel — comportement par défautpayant
node scripts/validate-moteurs-haloscan.js
Valide tous les candidats « à valider » par lots de 100, s'arrête proprement (sans erreur) dès que le pool restant ne permet plus un lot complet — relançable le mois suivant sans perte.
Run réel — plafonné (contrôle plus fin de la dépense)payant
node scripts/validate-moteurs-haloscan.js --limit 200
Traite au maximum 200 mots-clés puis s'arrête, quel que soit le crédit restant — utile pour un premier run prudent avant de laisser tourner le run complet.
Options disponiblesavancé
FlagEffetDéfaut
--min-volume NSeuil de rétention : volume ≥ N → « retenu », sinon « rejete »1
--batch-size NTaille d'un lot bulk() (réduit automatiquement de moitié en cas d'erreur)100
--limit NPlafonne le nombre total de mots-clés traités sur ce runillimité
Exemple combiné : node scripts/validate-moteurs-haloscan.js --min-volume 10 --limit 300
Premier run réel uniquement : un échantillon de la réponse brute Haloscan sera écrit dans data/keywords/_debug-bulk-response-sample.json — utile si le script signale « pas de volume exploitable » en masse (format de réponse jamais observé avant ce jour).

4 Promouvoir les candidats validés dans le tracking

Fusionne les candidats « retenu » dans l'onglet Suivi de tracking-mots-cles.xlsx (celui que lit le pipeline de publication), triés par volume avec l'éditorial. Ne perd jamais la progression de publication déjà en cours.

Régénération du tracking (Suivi)gratuit
python scripts/populate-tracking-xlsx.py
Idempotent : relancer sans nouveau candidat validé ne change rien. Fermer tracking-mots-cles.xlsx dans Excel avant de lancer.

5 Régénérer le maillage interne

Ajoute les liens (hub/sous-hub/latéraux/ancres) pour chaque nouveau cluster promu à l'étape 4. Fusionne avec l'existant, n'écrase jamais une entrée déjà en place.

Maillage — tous les silos automatiquementgratuit
python scripts/gen-maillage.py --all
Dérive automatiquement la paire (silo, hub) pour chaque silo présent dans l'onglet Suivi — recommandé plutôt que de retaper les 19 paires à la main.
Maillage — silos ciblés (ancienne méthode, toujours valide)avancé
python scripts/gen-maillage.py "Entretien & révision" "entretien-revision" "Pannes & diagnostic" "pannes-diagnostic"
Utile pour ne régénérer qu'un ou deux silos précis plutôt que la totalité.

6 Sauver les candidats rejetés (volume nul)

Au lieu d'abandonner un candidat à volume nul, cherche la vraie formulation recherchée autour de la même entité via keywords/similar (1 crédit creditKeyword, pool à 9999 — pas le pool contraint de la validation) + match/questions/related (gratuits). Réutilise le filtrage anti-bruit déjà éprouvé du P1.

Test à blanc (dry-run)gratuit
node scripts/rescue-rejected-candidats.js --dry-run
Sauvetage réelquasi gratuit (pool 9999)
node scripts/rescue-rejected-candidats.js --limit 20
Une alternative pertinente trouvée → le candidat repasse directement à retenu avec le vrai mot-clé et son vrai volume (pas besoin de repasser par la validation). Rien trouvé (ou doublon avec un mot-clé déjà pris) → rejete_definitif, jamais retenté.

🏭 Industrialisation — nouvelle niche / nouveau silo (2026-07-20)

Toute la taxonomie (silos, sous-cocons, auteurs) et les 7 moteurs programmatiques sont maintenant pilotés par une config déclarative (config/niches/<id>/niche.json + moteurs.json) au lieu d'être codés en dur en Python. Ajouter un silo ou une niche ne demande plus d'éditer aucun script.

Équivalence vérifiée : le moteur générique (scripts/moteur-engine.py + scripts/lib_py/moteur_types.py) reproduit à 100% les 4 153 candidats de la niche auto-mobilite (comparaison exhaustive mot-clé par mot-clé, 0 écart) — scripts/expand-moteurs.py délègue désormais à ce moteur générique.
Créer une nouvelle nichegratuit
python scripts/new-niche.py cuisine-recettes "Cuisine & Recettes du monde"
Scaffold config/niches/<id>/{niche.json, moteurs.json} + arborescence de données isolée (data/niches/<id>/) + classeur de tracking vierge. Ne touche jamais aux données d'une autre niche.
Ajouter un silo à une niche existantegratuit
python scripts/add-silo.py auto-mobilite "Nouveau silo" nouveau-silo --author A --sous-cocons "Sous-cocon 1" "Sous-cocon 2"
Enregistre le silo dans niche.json + crée un squelette vide dans seeds.json (sous-cocons déclarés, mots-clés à remplir à la main — jamais devinés). Fonctionne pour auto-mobilite comme pour toute nouvelle niche.
Collecter les mots-clés du nouveau silo (P1)payant
node scripts/fetch-keywords.js --niche auto-mobilite --silo "Nouveau silo"
Ajouter --dry-run pour simuler sans coût. Nécessite d'avoir rempli les mots-clés seed dans seeds.json au préalable.
Régénérer le tracking et le maillage pour une nichegratuit
python scripts/populate-tracking-xlsx.py --niche auto-mobilite
python scripts/gen-maillage.py --all --niche auto-mobilite
Identiques aux commandes de l'étape 4-5 plus haut, avec --niche explicite (défaut : auto-mobilite, donc ces commandes sans le flag continuent de fonctionner exactement comme avant).
Générer les candidats programmatiques d'une niche (si elle a des moteurs.json remplis)gratuit
python scripts/moteur-engine.py --niche auto-mobilite
Équivalent générique de l'étape 1 plus haut. Les 4 types de moteur réutilisables (croisement, entité seule, entité×angles, comparatif) sont documentés dans scripts/lib_py/moteur_types.py.
