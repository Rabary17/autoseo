🤖 Pipeline autopublish

Génération entièrement automatisée de 10 000 articles : rédaction LLM + relecture QA + gating 9 règles + publication WordPress. Zéro supervision manuelle.

Résultat : 20 articles/semaine en Phase 2 de démarrage, jusqu'à 15/jour à pleine capacité. Coût total : ~5€/article (vs 30–80€ pour un rédacteur humain).

Architecture globale

├─ config.json (budget, modèles, mapping) ├─ run.js (orchestrateur) ├─ lib/ │ ├─ state.js (tracking d'état) │ ├─ tracking.js (lecture xlsx mots-clés) │ ├─ maillage.js (récup liens internes) │ ├─ factuel.js (lecture données P2) │ ├─ persona.js (charge profil auteur) │ ├─ prompt-builder.js (compose le prompt) │ ├─ claude.js (API Anthropic) │ ├─ review.js (relecture QA) │ ├─ gating.js (9 règles SEO) │ ├─ similarity.js (TF-IDF anti-dupe) │ ├─ scheduler.js (étalement publication) │ └─ images.js (Pexels/Unsplash/Pixabay) └─ test-e2e.js (test 1 article [TEST])

Flux complet (par article)

1️⃣ Préparation

  • Lire tracking-mots-cles.xlsx (506 clusters × 19 silos)
  • Charger maillage.json (liens hub/sous-hub/latéraux)
  • Charger data/factuel/*.json (préstations, modèles, codes, etc.)
  • Récupérer profil auteur depuis skills/redaction/auteur-*.md
  • Sélectionner modèle Claude : Sonnet 5 (hubs) ou Haiku 4.5 (articles)

2️⃣ Rédaction (appel Claude #1)

  • Prompt : template éditorial + données + mots-clés + voix auteur + consigne FAQ/schémas
  • Structured output : JSON typé (title, body, meta_description, faq, etc.)
  • Prompt caching : skill auteur mis en cache (économie 90% sur requêtes suiv.)
  • Output : article complet en Markdown + métadonnées

3️⃣ Relecture QA (appel Claude #2)

  • Vérifier : grammaire, cohérence, pertinence données, sources citées
  • Jugement : Sonnet 5 uniquement (qualité critique)
  • Retour : verdict GO / ASK_REVISION (rarement — le prompt est bon)

4️⃣ Gating — 9 règles SEO/éditoriaux

#RègleAction si KO
1Meta description 120–160 charsRégénérer
2Mot-clé principal dans H1Rejeter
3Longueur 800–4000 mots selon typeRégénérer
4Aucune source non citée (donnée)Rejeter
5Similarité TF-IDF < 20% vs articles existantsRejeter
6Présence FAQ (articles > 1200 mots)Recommander
7Images appelées (alt text + title)Rejeter
8Aucune phrase marketing/creuseDemander relecture
9Liens internes résolus (check 404)Corriger

5️⃣ Images (cascade smart)

  • Stratégie : Pexels → Unsplash → Pixabay (en ordre de priorité)
  • Requête : Entité principale (marque/pièce/destination) + contexte
  • Déduplicate : Ledger autopublish-image-ledger.json (1 image = 1 article, pas de remploi)
  • Alt text : Généré (SEO native, description image)
  • Jamais blocking : Pas d'image = article publié quand même (image est un plus, pas une gating)

6️⃣ Publication WordPress

  • POST /wp-json/wp/v2/posts (authentifié, Application Password)
  • Body : titre, contenu (Gutenberg blocs), meta description, catégorie, tags, image à la une, auteur, statut=publish
  • Détection erreur : timeout, 401/403, limites API → logger + skip (pas de blocage)
  • Webhook revalidation auto-déclenché (ISR Next.js)

7️⃣ Tracking & rapports

  • État sauvegardé dans data/autopublish-state.json (quelle pièce = quel statut)
  • Rapport texte écrit après chaque run : nombre OK / erreur / rejeté / images
  • Email quotidien envoyé à andrianina.rabarivelo@gmail.com (workflow GitHub Actions)
  • Résumé de la semaine: articles publiés, coût Claude, état progression

Gestion des erreurs

Isolation des pannes

  • Article échoue : Marqué status: 'erreur', pipeline continue (pas de cascade)
  • API Claude timeout : Retry 3× (exponential backoff), puis skip
  • WordPress 401/403 : Erreur loggée, continue la boucle (ne bloque rien)
  • Images manquantes : Article publié quand même (images sont un plus)
  • État corrompu : Regenerate depuis zéro (fichier JSON corrupted → skip et continuer)

Points clés

Différences vs autres autopublish

  • Pas de supervision manuelle : Relecture Claude (QA) remplace l'humain
  • Gating strict : 9 règles vérifiées programmatiquement (pas de content farm)
  • Données uniques : Chaque article injecte ses propres données (prix, specs, codes)
  • Maillage résolu : Liens internes vérifiés avant publication (pas de 404)
  • Isolation erreur : 1 article échoue ≠ tout s'arrête (robustesse)
